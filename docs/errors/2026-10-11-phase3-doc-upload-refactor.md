# 错误记录：阶段 3 第一轮重构引入的两处缺陷

- 日期：2026-10-11
- 阶段：阶段 3 / 迭代 3.1–3.3（文件知识库 + 分块 + 片段检索）
- 严重程度：中（一处会丢接口、一处上传成功但响应缺字段）

## 错误 1：整段替换文档接口时误删 GET /api/conversations 路由装饰器

### 现象
用「起止锚点切片替换」方式把 documents 相关接口整段换成上传/详情/删除新实现后，路由总数从预期的 32 变成 31；枚举 `/api` 路由发现 `GET /api/conversations` 消失。函数 `list_conversations` 仍在，但上方的 `@app.get("/api/conversations")` 装饰器在切片边界被吞掉，前端对话列表会 404/405。

### 原因
替换锚点 `old_end` 取到了下一个路由的装饰器行，拼接新代码时只保留了函数体，未保留被吞并的装饰器。整段字符串替换跨越了不属于本次修改范围的接口。

### 处理
补回 `@app.get("/api/conversations")`，并用路由清单断言（enumerate app.routes）核对接口数量与路径。

### 教训
- 不要用跨多个无关路由的「大切片替换」；优先针对单个函数/装饰器做定点替换。
- 重构接口后必须枚举实际注册路由，与改动前清单对比，防止装饰器这类「函数还在、路由没了」的静默回归。

## 错误 2：上传成功但响应体缺 source_type（KeyError）

### 现象
`POST /api/documents/upload` 返回 200，但测试读取 `r.json()["source_type"]` 抛 `KeyError: 'source_type'`。

### 原因
`_store_parsed_document` 内部写入了 source_type，返回字典却只回了 `{id,filename,status,chunk_count}`，调用方与前端期望回显来源类型。

### 处理
返回值补充 `source_type` 与 `file_ext`。

### 教训
- 存储层写入字段与 API 回显字段要对齐；新增入库字段时同步检查返回 DTO 与前端读取字段。

## 附带：片段级改造后旧测试夹具字段过时
`used_documents` 由文档级（id/content）改为片段级（document_id/chunk_id/...）后，阶段 2 的注入测试仍按旧结构构造夹具，触发 `KeyError: 'document_id'`。这是接口形态演进的预期联动，已把夹具更新为片段形态。教训：改接口响应结构时，全局搜索该字段的所有构造点（不仅是调用点）。
