# 2026-10-11 本地目录连接器 max_depth 边界语义反复返工

## 错误现象
3.5.2 本地目录连接器测试 `test_max_depth_and_nonrecursive_modes` 连续失败/返工：
- 初版 `if depth >= max_depth` 时，`max_depth=1` 仍同步到第一层子目录（测试预期只看根目录文件）。
- 改成 `depth + 1 > max_depth` 后，1 层子目录可进（与最初测试预期相反）。
- 一度又改成 `depth + 1 >= max_depth`，并把合法下限从 1 改成 0，连带出现两处测试预期失败（max_depth=0 用例、文件顺序断言）。

## 根因分析
不是单纯的“差 1” off-by-one，而是**先写了实现和测试，却没先把深度语义钉死**，导致实现、配置校验、测试三者各按一种理解走：
1. “只看根目录文件”这个需求其实由 `recursive=false` 承担，不应再让 `max_depth=1` 兼职表达同一件事。
2. 深度没有明确定义“根目录算 0 还是算 1”，于是 `>` / `>=` / 下限 0 还是 1 来回摇摆。
3. 断言用有序列表比较 `os.walk` 的产出，但目录/文件遍历顺序在不同环境不保证稳定，制造了与边界无关的额外失败。

## 最终确定的语义（已回写计划与前端提示）
- 根目录深度 = 0；`max_depth=N` 表示允许向下进入 N 层子目录（默认 6，范围 0–12）。
- `recursive=false`：只看授权根目录直接包含的文件，忽略所有子目录（此时忽略 max_depth）。
- 下钻判断：在深度 depth 的目录里，是否进入某子目录用 `depth + 1 > max_depth` 判定。
- 测试对文件集合用集合/无序断言，不依赖遍历顺序。

## 解决方案及验证
统一为上述语义后：配置校验允许 `max_depth` 0–12；测试改为非递归只看根、`max_depth=0` 等同不下钻、默认深度能到一层子目录，并用集合比较。
- `tests/test_local_connector.py` → 8 passed, 1 skipped（符号链接用例在无权限环境跳过）。
- 全量 `pytest -q` → 97 passed, 1 skipped。

## 预防
- 涉及“层数/数量/偏移”这类参数，先在计划里写死基线定义（根是 0 还是 1）与边界含义，再同时落地实现与测试，避免边写边改。
- 对文件系统遍历结果一律用集合断言，不假设顺序。
- 一个参数只表达一件事：是否递归用 recursive，递归多深用 max_depth。
