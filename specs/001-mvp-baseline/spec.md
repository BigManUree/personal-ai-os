# Feature Specification: Personal AI OS MVP Baseline

**Feature Branch**: `001-mvp-baseline`

**Created**: 2026-10-14

**Status**: Draft

## User Scenarios & Testing

### User Story 1 - 本机个人工作台与档案管理 (Priority: P1)

用户在本机浏览器打开应用，查看和更新个人档案，所有数据保存在本地，无需配置外部服务即可使用核心功能。

**Why this priority**: 个人档案是个人 AI OS 的一切数据基础，也是无外部服务即可演示的入口。

**Independent Test**: 启动应用后，用户可在浏览器完成档案的查看与更新，并能在重新打开后看到持久化的档案。

**Acceptance Scenarios**:

1. **Given** 应用已启动且用户通过本机地址访问，**When** 用户打开首页，**Then** 用户看到个人档案界面并可查看现有档案内容。
2. **Given** 用户修改了档案字段，**When** 用户保存修改，**Then** 系统持久化新档案并在后续访问中返回更新后的内容。
3. **Given** 应用未配置云端模型 Key，**When** 用户使用聊天入口，**Then** 系统以本地演示逻辑回应，不中断核心流程。

---

### User Story 2 - 长期记忆管理 (Priority: P1)

用户积累对话与信息后，系统从对话中提取候选记忆；用户审核通过后成为长期记忆，可检索并查看引用来源；系统对重复/冲突给出提示，支持过期和修订历史。

**Why this priority**: 长期记忆是个人 AI OS 的核心差异化能力，支撑后续一切个性化行为。

**Independent Test**: 用户可独立完成从候选提取、审核、检索到查看引用来源的完整闭环。

**Acceptance Scenarios**:

1. **Given** 存在足够的对话内容，**When** 系统执行候选提取，**Then** 生成待审核的记忆候选列表。
2. **Given** 用户审核某候选，**When** 用户批准或拒绝，**Then** 批准项成为长期记忆，拒绝项不再进入记忆。
3. **Given** 用户搜索某主题，**When** 用户输入关键词，**Then** 系统返回相关记忆并附带引用来源。
4. **Given** 新候选与现有记忆重复或冲突，**When** 系统比对，**Then** 向用户提示重复或冲突信息。

### User Story 3 - 文档知识库 (Priority: P1)

用户上传常见格式文档（如 PDF、Word、Markdown、纯文本），系统解析并存储文本内容，用户可按关键词检索到文档片段并查看来源页码/标题；重复文档不会重复入库。

**Why this priority**: 文档知识库提供可检索的个人资料沉淀能力，是 MVP 的关键价值点。

**Independent Test**: 用户上传多份文档后，可用关键词检索到对应片段并定位来源。

**Acceptance Scenarios**:

1. **Given** 用户上传一份受支持格式的文档，**When** 解析完成，**Then** 文档内容被保存并可检索。
2. **Given** 用户重复上传同一份文档，**When** 系统校验内容，**Then** 重复文档被识别并跳过重复入库。
3. **Given** 用户检索某关键词，**When** 命中文档片段，**Then** 返回结果包含片段内容及来源页码/标题。

### User Story 4 - 项目、目标、任务、对话与审批记录 (Priority: P2)

用户可记录项目、目标、任务、对话与审批事项，作为个人工作流的可追溯数据。

**Why this priority**: 这些记录支撑个人任务管理与后续分析，但可作为增量能力独立交付。

**Independent Test**: 用户可完成项目/目标/任务的创建、更新与查看，并记录对话与审批。

**Acceptance Scenarios**:

1. **Given** 用户创建项目并关联目标与任务，**When** 用户保存，**Then** 数据可被查看和更新。
2. **Given** 用户记录一次对话或审批，**When** 用户保存，**Then** 记录可被检索和追溯。

### User Story 5 - 行为分析、画像与建议反馈闭环 (Priority: P2)

系统记录行为事件，提供确定性分析和周期对比；生成个人画像条目与证据驱动建议；用户对建议给出反馈和结果记录，形成闭环。

**Why this priority**: 画像与建议体现"AI OS"的主动价值，基于已有行为数据即可运行。

**Independent Test**: 用户可查看行为分析结果、画像条目与建议列表，并对建议提交反馈。

**Acceptance Scenarios**:

1. **Given** 系统已记录行为事件，**When** 用户查看分析，**Then** 用户获得确定性统计结果与周期对比。
2. **Given** 系统基于证据生成画像条目和建议，**When** 用户查看，**Then** 建议附带证据说明且用户可提交反馈与结果。

### User Story 6 - 只读数据源连接与定时同步 (Priority: P2)

用户可配置本地目录、GitHub 仓库和通用 HTTP API 为只读数据源，逐源选择是否定时同步，并查看同步日志；凭据加密保存。

**Why this priority**: 连接器扩展个人数据来源，是外部数据整合的通道。

**Independent Test**: 用户可添加数据源、执行一次同步并查看同步结果与日志。

**Acceptance Scenarios**:

1. **Given** 用户添加一个受支持的数据源并填写配置，**When** 用户执行同步，**Then** 系统拉取只读条目并记录同步日志。
2. **Given** 用户对某数据源开启定时同步，**When** 到达同步时机，**Then** 该源被自动同步且不影响其他源。
3. **Given** 连接器配置包含凭据，**When** 系统保存配置，**Then** 凭据以加密形式存储，不出现明文。

### User Story 7 - 提醒与到期通知（测试渠道） (Priority: P3)

用户可设置提醒及规则/安静时段，系统按调度推进提醒状态；提醒到期生成通知记录（事件与投递分离），当前通过内置测试渠道消费；自动调度默认关闭，真实外部通知未实现。

**Why this priority**: 提醒基础设施已完成，但对外投递受限，属于低风险增量能力。

**Independent Test**: 用户可创建提醒并手动触发状态推进，验证到期后生成通知记录。

**Acceptance Scenarios**:

1. **Given** 用户创建一条带触发时间的提醒，**When** 调度推进到期，**Then** 提醒状态被正确推进并生成唯一通知事件。
2. **Given** 通知处于待投递状态，**When** 测试渠道消费，**Then** 投递记录更新，失败进入重试并最终可达死信上限。
3. **Given** 应用未显式启用自动调度，**When** 应用启动，**Then** 自动调度不运行，提醒仅通过手动触发推进。

### Edge Cases

- 重复上传同一文档时，系统如何避免重复入库？
- 新记忆候选与已有记忆重复或冲突时，用户如何获知并处理？
- 未配置云端模型 Key 时，聊天、记忆提取与画像生成等依赖模型的功能如何降级？
- 数据源同步失败或网络异常时，同步日志如何记录，其他源是否受影响？
- 提醒调度与通知消费同时运行时，多进程/多 worker 场景下如何避免重复处理？
- 连接器配置包含敏感凭据时，如何保证不泄露到日志或普通配置？
- 应用被非本机地址访问或遇到跨站状态变更请求时，系统如何防护？

## Requirements

- **FR-001**: 系统 MUST 提供本机浏览器访问的个人工作台，支持个人档案的查看与更新。
- **FR-002**: 系统 MUST 在未配置云端模型时提供可用的本地演示能力，不阻断核心功能。
- **FR-003**: 系统 MUST 支持从对话内容中生成待审核的记忆候选。
- **FR-004**: 系统 MUST 支持用户对记忆候选的批准/拒绝审核，并持久化审核结果。
- **FR-005**: 系统 MUST 在候选记忆与已有记忆重复或冲突时提示用户。
- **FR-006**: 系统 MUST 支持长期记忆的过期管理与修订历史。
- **FR-007**: 系统 MUST 支持按关键词检索记忆与文档片段，并附带引用来源（如来源页码/标题）。
- **FR-008**: 系统 MUST 支持上传 PDF、Word、Markdown、纯文本文档并解析其文本内容。
- **FR-009**: 系统 MUST 通过内容校验识别重复文档并跳过重复入库。
- **FR-010**: 系统 MUST 支持项目、目标、任务的创建、更新与查看。
- **FR-011**: 系统 MUST 支持对话记录与审批记录的保存与追溯。
- **FR-012**: 系统 MUST 记录行为事件，提供确定性分析与周期对比结果。
- **FR-013**: 系统 MUST 生成个人画像条目与证据驱动建议。
- **FR-014**: 系统 MUST 支持用户对建议提交反馈与结果记录。
- **FR-015**: 系统 MUST 支持配置本地目录、GitHub 仓库与通用 HTTP API 三类只读数据源。
- **FR-016**: 系统 MUST 支持逐源选择是否定时同步，并记录同步日志。
- **FR-017**: 系统 MUST 以加密形式保存连接器凭据，禁止在普通配置中出现明文密钥。
- **FR-018**: 系统 MUST 支持提醒的创建、规则与安静时段设置，并正确推进提醒状态。
- **FR-019**: 系统 MUST 在提醒到期时生成唯一通知事件与投递记录（事件与投递分离）。
- **FR-020**: 系统 MUST 支持投递重试、指数退避、死信与运行中记录恢复；当前仅通过内置测试渠道消费。
- **FR-021**: 系统 MUST 在未显式启用时默认关闭自动提醒调度与通知消费服务。
- **FR-022**: 系统 MUST 在并发或多实例运行场景下保证提醒调度不重复执行。
- **FR-023**: 系统 MUST 仅允许本机访问，并防护跨站状态变更与提示注入。

### Key Entities

- **个人档案 (Profile)**: 用户的基本信息与画像基础，个人 AI OS 的数据锚点。
- **长期记忆 (Memory)**: 经用户审核的可检索个人记忆条目，含候选、状态、修订与引用来源。
- **文档 (Document)**: 上传并解析的知识库内容，含分块片段与来源定位。
- **项目/目标/任务 (Project/Goal/Task)**: 个人工作流的结构化记录。
- **对话 (Conversation)**: 与应用的交互记录，是记忆提取与行为分析的输入。
- **审批 (Approval)**: 需要追溯的审批事项记录。
- **行为事件 (Behavior Event)**: 只追加的用户行为记录，支撑分析。
- **画像条目 (Profile Item)**: 由证据生成、供用户确认的个人特征条目。
- **建议 (Recommendation)**: 证据驱动的行动建议，含反馈与结果闭环。
- **数据源 (Data Source)**: 本地目录、GitHub、HTTP API 等只读连接器，含同步日志。
- **提醒 (Reminder)**: 用户设置的提醒事项，含规则、安静时段与状态机。
- **通知事件/投递 (Notification Event/Delivery)**: 提醒到期的业务事实与各渠道投递生命周期记录。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 用户在 1 分钟内可完成个人档案的查看与更新，且数据在重启后仍可访问。
- **SC-002**: 用户可在 2 分钟内完成从上传文档到关键词检索到片段的完整流程。
- **SC-003**: 记忆候选审核流程支持批量操作，检索结果在 2 秒内返回。
- **SC-004**: 重复文档 100% 被识别并跳过，不产生重复知识条目。
- **SC-005**: 连接器同步失败不影响其他数据源，同步日志可追溯最近 100 次记录。
- **SC-006**: 提醒到期后 100% 生成唯一通知事件，重复触发不产生重复事件。
- **SC-007**: 未配置云端模型时，核心个人工作台、记忆审核、文档检索功能 100% 可用。
- **SC-008**: 应用仅接受本机访问，任何外部访问请求被拒绝。

## Assumptions

- 本基线规格面向单用户、本机使用的个人应用，多用户/公网部署不在当前范围。
- 数据默认保存在本机，用户可自行备份；不承诺多机/网络盘共享或云端同步。
- 自动提醒调度与通知消费默认关闭；真实外部通知（邮件、短信、Webhook、桌面）未实现，当前仅测试渠道。
- 未配置云端模型 Key 时，依赖模型的增强能力（如自动记忆提取、画像候选、建议润色）降级为空结果或提示，不阻塞核心功能。
- 上传的原始文件不以独立磁盘文件长期保存，以解析文本与元数据为主。
- 现有系统基础设施（本地工作台、检索、记录存储）作为后续迭代的复用基础。
- 本基线规格描述的是当前已实现能力，后续迭代以其为基准增量演进。
