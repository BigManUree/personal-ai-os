# Spec 014：向量检索（千问 text-embedding）

## 背景

检索此前是 FTS5 trigram + 词法 bigram 打分：同义改写、跨语言、概念相近但用词不同的查询召不回来（实测「晨练习惯」对「每天早晨跑步五公里」词法 0 分）。

## 目标（FR）

1. **FR-101** 用千问 `text-embedding-v4`（1024 维，OpenAI 兼容 `/embeddings`）为每个 chunk 生成向量，落 `chunk_embeddings` 表。
2. **FR-102** 混合打分：词法分 + FTS bm25 加成 + **向量相似度 × 3.0**（仅 `sim ≥ 0.45` 才算，低于阈值不注入噪声）。
3. **FR-103** 入库自动索引：文档创建后异步补齐向量（后台线程，**不把网络往返压在写事务里**）。
4. **FR-104** 运维端点：`GET /api/embeddings/status`（模型/维度/覆盖率）、`POST /api/embeddings/reindex?limit=`（分批回填）。
5. **FR-105** 全链路降级：无配置/网络失败/维度不符时，检索退化为纯词法，上传与对话不受影响。

## 非目标

- 不做 ANN 索引（单用户规模暴力余弦足够；10 万条以内 < 100ms）
- 不做多模态向量（图片/音频）
- 不引入外部向量库（保持单文件 SQLite 部署）

## 关键决策

| 决策 | 理由 |
|---|---|
| 阈值 0.45 | 实测：相关句 0.72 / 无关句 0.27，0.45 两侧余量最大 |
| 权重 ×3.0 | sim=0.7 → +2.1，足以让零词法重叠的片段进结果又不压过强词法命中 |
| 异步索引 | 上传接口不等 embedding（避免几十秒阻塞）；失败仅记日志 |
| 派生数据 | 表可整表重建；模型名随行存储，换模型自动重算（查询按当前模型过滤） |
| 千问 MaaS | 用户提供的工作空间端点；`8011930` 是控制台部署 ID 不是 API 模型名，实际模型用 `text-embedding-v4` |

## 验证

见 `docs/testing.md` 0.20 节：真实端点三组查询（晨练习惯/查询性能/今天吃什么）、覆盖率 16/16、587 用例、6 个新契约测试（mock 向量保证确定性）。
